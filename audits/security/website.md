# Security audit: pulse-website (2026-10-31)

## Scope

- Issue: lorenzh/pulse-meta#539 (periodic security audit of `main` in pulse-website).
- Audit date: 2026-10-31 (UTC).
- Repositories and examined commits:
  - website `dcb616275ef3ed87c2ff8588d00b98d46b8294d6` (newest `main`, clone in `.repos/website`).
  - meta `eda99640c61e5d33031664d8d384d797faf40c1d` (`docs/approved-packages.md`).
  - config `86896e9ff02e6458e431aa3417ee81d3b1cbc335`: the pulse-config commit that website pins in `package.json` and `ci.yml`. Its `check.yml` was read through the GitHub API (the shallow clone in `.repos/config` is at `01a57a7e3f7c61aaa2a65f54d8b780a51efe58dc` and lacks that commit).
  - Docs sources for the offline build: notify `584eabd05abcadc8f5a1035307e2c09a7a84c933`, contract `ebcbbb613328494185833f7133f1242910986948` and kit `6a06ec25d26d90be12eba133972b59077dd0e17d` (the SHAs pinned in `docs.config.json`). The pinned SHAs of api, probe and status are missing from the shallow clones, so their docs were taken from the clone heads (api `a72baee04dd415c82e1a48079475690957c8b166`, probe `85720d384a7e146c47d4436b14b3e85379e3deb4`, status `3f80bda9d7ed17127a43bcf51b71cd1e05add9b0`). Only the content differs; the code under test is the same.
- Method: a copy of website in `mktemp -d`, `bun install --frozen-lockfile`, Bun 1.4.0 on Linux. `bun run check` passes (lint, typecheck, 177 tests, exit 0). The docs cache (`.cache/docs/`) was filled from the local clones, so `bun run build` ran offline. Every build ran with `HTTPS_PROXY` set to a dead local port, so no request could leave the host. `bun run check:links` and `bun run check:a11y` ran on the built `dist/`. Chromium for `check:a11y` came from `bunx playwright install chromium` (Playwright 1.64.1 from the lockfile). The hostile-input probes are scripts outside the repository. They call the website modules directly, with fake `fetch` functions and loopback servers. The full reproductions are not committed.
- Surface: pulse-website is a static site generator, with no deployment and no application server. Its trust boundaries are `docs.config.json`, the Markdown fetched from `raw.githubusercontent.com` at pinned SHAs (and its cache), the GitHub API and `git ls-remote` answers in `docs:bump`, the command-line arguments of `docs:bump`, and the loopback static server that `check:a11y` starts. The built pages ship only the Preact islands; the islands read nothing untrusted beyond `localStorage.theme` (only `light` or `dark` is used) and `data-copy` (fixed at build time).

## Issue candidates

The commands below describe each check without its input. The reproductions stay outside the repository.

### SEC-1 `security-website-2026-10-31-1` (P2): HTML injection through the code-block highlighter

- Location: `src/docs/highlight.ts:92` to `:93` (`LANGUAGES[language]`, then `tokenize(code)`), called from `src/docs/markdown.ts:100`. The language comes from the info string of a fenced code block (`markdown.ts:89`). `src/docs/markdown.ts:61` and `src/components/DocsPage.tsx:89` rely on "raw HTML is escaped".
- Class: HTML injection (stored, build time) through a prototype-chain lookup with an untrusted key. `LANGUAGES` is a plain object. A language that names an inherited `Object.prototype` member returns a built-in function instead of a tokenizer. For one such name, the function returns the code text as it is, so `escapeHtml` never runs on it.
- Check: render a fenced block whose language names an inherited member, with markup as its body, through `renderMarkdown`. Then add the same block to one cached doc, run `bun run build`, `bun run check:links` and `bun run check:a11y`, and query the page in Chromium. Exit codes: probe 0 (it reports the effect), build 0, check:links 0, check:a11y 0.
- Effect: `rawMarkupInOutput=true` for that language and `false` for `json`, `yaml`, `bash`, `html`. In Chromium: `{"paragraphElement":true,"insideCodeElement":true,"linkElement":true,"linkHref":"https://pulse.invalid/login"}`. `check:links`: `links ok, csp ok on 39 pages`. `check:a11y`: `a11y ok`.
- Impact: whoever lands a Markdown change in a published `docs/*.md` of one of the six docs repositories can put arbitrary HTML into the pulse website. Examples are off-site links and fake text or notices, and every CI gate passes. The source is an ordinary fenced code block, so a reviewer of the docs pull request reads it as code, and `docs:bump` pulls the change in. What the gates still stop: the CSP meta tag has no `'unsafe-inline'`, so it blocks inline script; `check:links` fails on an extra `<script` (`2 inline scripts, expected 1`), and axe in `check:a11y` fails on a `meta` refresh (`meta-refresh (critical)`). The currently pinned docs use only `sh`, `json`, `text`, `yaml`, `js`, `cron` and no language, so no published page is affected today.
- Fix direction: look up the tokenizers and labels in a `Map`, or in objects created with `Object.create(null)`, or check `Object.hasOwn` first. Always escape the result of a tokenizer that is not one of the own functions. Add a test that renders a block for each `Object.prototype` member name and expects escaped text.

### SEC-3 `security-website-2026-10-31-3` (P3): docs cache written in place; a torn file is trusted from then on

- Location: `src/docs/fetch.ts:48` (`writeFile(file, text)` on the final path) and `:31` (a cache hit returns the file without any check).
- Class: non-atomic write of a cache that is never checked again.
- Check: `strace -f -e trace=openat,rename,…` of a cache miss with a fake `fetch`. Then 10 runs that `kill -9` the process while it writes a 400 MB doc, then one `loadDocFile` on the same cache directory. Exit 0 for each step.
- Effect: `openat(…/lorenzh__pulse-kit/<sha>/docs/index.md, O_WRONLY|O_CREAT|O_LARGEFILE, 0666) = 7` and `rename calls: 0`. After `kill -9`, 6 of 10 files are torn, for example `size 400000010, x bytes 29360119 of 400000000, last byte '\0'`. The next load prints `400000010 chars, fetch calls 0, ends with newline false`.
- Impact: a build that is stopped while it writes a cache file (Ctrl-C, OOM kill, a power cut) leaves a truncated or zero-filled doc. The cache key is an immutable SHA, so each later build publishes that doc as it is, until a person deletes `.cache/`. CI is not affected: it starts with no cache.
- Fix direction: write to a temp file in the same directory, then `rename` it into place. Optionally store the length or a hash of the fetched text and check it on a cache hit.

### SEC-4 `security-website-2026-10-31-4` (P3): one malformed percent-escape stops the static server of `check:a11y`

- Location: `src/build/static-server.ts:17` (`decodeURIComponent` without a guard), called at `:26`, outside the `try` of `handle`. `handle` runs as `void handle(req, res)` at `:43`.
- Class: an unguarded decoder throws on request input, and the promise rejection is unhandled.
- Check: start `startStaticServer(dist)` and send one GET whose path has a malformed percent-escape. With the probe's own `unhandledRejection` handler, also send two such requests and the normal targets. Exit 1 without the handler.
- Effect: without a handler the process ends: `URIError: URI error at fileForUrl (src/build/static-server.ts:17:17)`, `exit=1`. With a handler, the request gets `no answer within 2 s`, and `unhandledRejection: URIError: URI error` is logged per request. Escaping paths (`../`, `%2f`, `%2e%2e`, `%5c`, `%00`) correctly give 404.
- Impact: any local process that can reach the loopback port can stop the `check:a11y` run, and a page or asset URL with such an escape could stop it too (not tested). The server runs only on `127.0.0.1` during checks.
- Fix direction: catch the `URIError` in `fileForUrl` (return `undefined`, then 404), or move the call inside the `try`. Never leave the request promise unhandled.

### SEC-5 `security-website-2026-10-31-5` (P3): `parseDocsConfig` throws `RangeError` or `TypeError` instead of `DocsConfigError`

- Location: `src/docs/config.ts:41` (`String(file)` in the error message for a `files` entry that is not a string).
- Class: the validator throws on some input types. The error-message conversion of the rejected value is unguarded.
- Check: `parseDocsConfig(JSON.parse(<config text>))` with a `files` entry that is a nested array of depth 1,000, 10,000 and 100,000, and, through the API, with an object that has no prototype. `JSON.parse` alone accepts depth 10,000. Exit 0 (the probe reports each case).
- Effect: depth 1,000 gives `DocsConfigError: repos.kit.files: "x" is not a docs/*.md path`. Depth 10,000 and 100,000 give `RangeError: Maximum call stack size exceeded.`, and the object without a prototype gives `TypeError: No default value`.
- Impact: low. `docs.config.json` is a repository file, and the build fails either way. But the error names neither the field nor the file, and it breaks the checklist rule that validators never throw.
- Fix direction: describe the rejected value by `typeof` (or a bounded `JSON.stringify` in a `try`) instead of `String(value)`.

## Notes

Findings that are not issue candidates:

- **SEC-2 `security-website-2026-10-31-2` (P3)**: other inherited member names as a code-block language throw out of `renderMarkdown`, and they put native function text into the block's `aria-label`. Location: `src/docs/highlight.ts:92` to `:93` and `src/docs/markdown.ts:52` (`LANGUAGE_LABEL[lang]`). Check: the same `renderMarkdown` probe as SEC-1, for 10 `Object.prototype` member names. Exit 0. Effect: 7 names give `TypeError: undefined is not an object (evaluating 'highlight(text, language)')` or `TypeError: tokenize is not a function`, which stops the build with a bare `TypeError` that names neither the repository nor the file. Two names give `ariaLabel="function toString() {\n    [native code]\n}"` and similar. The fix of SEC-1 fixes this too.
- **SEC-6 `security-website-2026-10-31-6` (P3)**: `bun run docs:bump <key>` accepts `Object.prototype` member names as repository keys. Location: `scripts/bump-docs.ts:38` (`DOC_REPOS[key]`; only a missing value is rejected). Check: run `docs:bump` with an unknown key and with three member names, with a fake `git` on `PATH`. Exit 1 each. Effect: an unknown key gives `error: unknown repo "nope", expected one of api, probe, status, notify, contract, kit`. A member name instead runs `git ls-remote https://github.com/<native function text>.git refs/heads/main` (or `…/[object Object].git`). Impact: only the person running the script supplies the key, and git fails before anything is written. Fix direction: check `Object.hasOwn(DOC_REPOS, key)` or use a `Map`.

Other notes:

- **N1** (link check scope): `unsafeRefs` (`src/build/html-refs.ts:126`) reads only `href`, `src`, `action`, `poster` and `srcset`, as the README states. In the probe, a `javascript:` URL in `xlink:href`, `formaction` or `<object data>` is not flagged, and neither is `srcdoc`. Of two equal `href` attributes the first counts, as in the browser. The CSP meta tag (`script-src` without `'unsafe-inline'`, `object-src 'none'`, `form-action 'none'`) blocks these. Today they could reach a page only by hand-written content or through SEC-1. A fuzz of `isSafeUrl` against the WHATWG URL parser (2,548 variants of 7 schemes with leading controls, inner tabs and newlines, and encoded colons) found 0 values judged safe that parse to another scheme.
- **N2** (environment lookup): Bun's `fetch` in `scripts/build.ts:21` and `scripts/bump-docs.ts:19` uses `HTTPS_PROXY` and `HTTP_PROXY`. The probe saw `CONNECT raw.githubusercontent.com:443` and `CONNECT api.github.com:443` at a local listener. TLS stays end to end; the token is not in the CONNECT head.
- **N3** (no size cap on upstream answers): `src/docs/fetch.ts:45` (`response.text()`) and `scripts/bump-docs.ts:25` (`response.json()`) read whole bodies; a 400 MB fake body was accepted. The hosts are fixed and the docs are pinned by SHA.
- **N4** (upstream text in errors): `scripts/bump-docs.ts:25` passes a `response.json()` parse error through unchanged. In Bun, that message can quote the first bad token of the body (seen in the notify audit, SEC-2 there). It was not reproduced here, because the URL is fixed to `api.github.com`.
- **N5** (`docs.config.json` pattern): `REPO` (`src/docs/config.ts:15`) accepts `.` and `..` segments, so `../..` passes. The URL `https://raw.githubusercontent.com/../../<sha>/…` keeps its host, and the cache folder is the single name `..__..`. `KEY` accepts `constructor`; assigning to a plain object stays an own property, and the nav check then rejects the unknown key.
- **N6** (`bun audit`): exit 1, `minimatch@10.2.6 moderate: GHSA-g3hv-75wg-m249 (<11.0.1)`. `bun pm why minimatch`: through `@eslint/config-array@0.23.5` from `eslint@10.13.0`, a dependency of pulse-config; dev only, not in the production install.
- **N7** (`isSafeUrl` input type): `isSafeUrl` throws `TypeError` for `undefined`, `null`, a number, an object, a symbol and a bigint. Its parameter is typed `string`, and all three callers pass strings from marked tokens or the tag reader.
- **N8** (`dist/` writes): `scripts/build.ts:36` to `:45` removes `dist/` and writes each page with `writeFile` in place. A stopped build leaves a partial `dist/`; there is no deployment yet. Not reproduced with a kill test.
- **N9** (CI browser download): the `site` job runs `bunx playwright install --with-deps chromium`. Playwright is pinned at 1.64.1 by the lockfile, but the browser build comes from the Playwright CDN at run time, with no hash in the repository.
- **N10** (marked on deep nesting): `renderMarkdown` on a list nested 2,000 levels deep (about 4 MB) took 133,878 ms; 5,000 nested blockquotes took 481 ms. This is build time only, from pinned docs, and the `site` job has a 20-minute timeout.
- **N11** (static server methods): the static server answers `POST`, `PUT` and `PATCH` like `GET` and never reads the body. It writes nothing.
