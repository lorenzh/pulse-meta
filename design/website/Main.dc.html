Uptime monitor · Status page · MIT licensed

Know when it breaks. Tell people when it’s back.

pulse checks HTTP endpoints, TLS certificates and cron jobs from several locations, decides by quorum, and keeps a calm public status page. Incidents reach Slack, Teams, email or a signed webhook. Self-hosted with one Docker Compose file.

Features

Everything a small team needs, nothing it has to babysit

HTTP checks

Status code, latency objective, a keyword in the body, retries and timeouts per check.

TLS certificates

Days until expiry for every host, with a warning threshold you set.

Heartbeats

Cron jobs and workers ping pulse. No ping within the period and grace opens an incident.

Quorum

Probes in several locations. A check is down only when the majority agrees.

Maintenance windows

Planned work shows as maintenance, not as an outage, and opens no incident.

White-label status page

Your name, logo, colours and fonts. Light and dark, accessible, works without tracking.

Notifications

Slack, Microsoft Teams, email and HMAC-signed webhooks, with reminders while an incident stays open.

Metrics and health

Every service exposes /metrics for Prometheus and a health endpoint for your orchestrator.

How it works

Four small services, one shared contract

Probes run the checks and post results. The API decides the state of every check and keeps the incidents. The status page and the notifier only read from it.

One per location pulse-probe Runs HTTP and TLS checks on schedule and reloads them from the API.
POST /results
The source of truth pulse-api Stores results in SQLite, applies quorum and maintenance, opens and resolves incidents, takes heartbeat pings.
GET, read only
pulse-status The public page, redacted and cached.
pulse-notify Sends opened, resolved and reminder messages, at least once.

All four share pulse-contract: the wire types, runtime validators and a version header, so a mismatched deploy fails loudly instead of quietly.

Configuration

Checks live in one file

Describe each check in checks.json. Unknown keys and out-of-range values stop the start with one line that names the field, so typos never pass silently.

Read the configuration guide
checks.json
{
  "checks": [
    {
      "id": "website",
      "name": "Website",
      "url": "https://example.com/",
      "intervalMs": 10000,
      "latencyObjectiveMs": 500,
      "keyword": "ok"
    },
    {
      "id": "nightly-backup",
      "type": "heartbeat",
      "period": 86400000,
      "grace": 3600000
    }
  ]
}
