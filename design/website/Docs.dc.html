Quick start

Run the API, one probe, the status page and the notifier on one machine with Docker Compose. The example check watches the status page itself, so you see a state within seconds.

5 minDocker Compose 2.23 or newerUpdated 29 October 2026

Before you start

  • Docker with Compose 2.23 or newer.
  • Access to github.com: the probe, status and notify images are built from their repositories.
  • Ports 3000 and 8080 free on the host, or other ports set in .env.

1. Get the Compose file

The Compose file for the whole stack lives in pulse-api.

{{cb.b1.tip}}
$ git clone https://github.com/lorenzh/pulse-api.git
$ cd pulse-api

2. Create the probe token

Copy the example settings and replace the placeholder token with a random one. Without a valid token the API stops at start.

{{cb.b2.tip}}
$ cp .env.example .env
$ openssl rand -hex 32
# paste the output as PULSE_PROBE_TOKEN in .env
Warning The tokens in the examples and the demo profile are public. pulse refuses the example placeholder, but treat every token you did not generate yourself as known.

3. Start the stack

{{cb.b3.tip}}
$ docker compose up -d --build

Open http://localhost:8080. The probe runs the example check right away and then every 10 s, so its state leaves unknown within seconds.

4. Add your own checks

Edit compose/checks.json and restart the API. Probes pick up the change on their own within a minute.

{{cb.b4.tip}}
$ docker compose restart api

Compose settings

Variable Default Meaning
PULSE_PROBE_TOKENnoneToken of the probe. Compose also writes it to the API’s tokens file.
PULSE_LOCATIONdefaultLocation name of the probe, shown per result.
PULSE_API_PORT3000Host port of the API, bound to 127.0.0.1.
PULSE_STATUS_PORT8080Host port of the status page.
