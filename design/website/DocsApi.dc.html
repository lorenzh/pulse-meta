REST API

pulse-api answers JSON on port 3000. Only probes write, with a bearer token; every read route is open, so keep the API itself private and publish the status page instead.

Wire version Every response carries the header x-pulse-contract: 1. Clients refuse an answer with another version instead of guessing.

POST/results

A probe reports one check run. The token decides the location; the API checks the order of results per location and ignores late ones for the state.

Field Type Rule
checkIdstringA configured, active check.
timestampintegerEpoch ms, at most 60 s ahead of the API clock and 7 days behind it.
status"up" · "degraded" · "down"Required.
statusCodeinteger · nullnull when no response arrived, else 100 to 599.
latencyMsnumber0 to 86,400,000.
reasonstring · nullAt most 1,000 characters.
$ curl -X POST http://localhost:3000/results \
-H "Authorization: Bearer $PULSE_PROBE_TOKEN" \
-H "Content-Type: application/json" \
-d '{"checkId":"example","timestamp":1793265326003,
"status":"up","statusCode":200,"latencyMs":42,"reason":null}'
HTTP/1.1 204 No Content

GET/checks

Every active check with its state, the last result per location, and the maintenance window when one is running. Removed checks are left out.

200 · application/jsonshortened
[{
  "id": "example",
  "name": "Example endpoint",
  "intervalMs": 10000,
  "state": "down",
  "consecutiveDown": 4,
  "lastResultAt": 1793265326003,
  "lastReason": "HTTP 503",
  "locations": [{
    "location": "east",
    "stale": false
  }]
}]

GET · POST/heartbeat/:id

A cron job or worker pings its heartbeat check. Prefer the header; the path form puts the secret into logs of proxies and cron mail.

$ curl -fsS -X POST http://localhost:3000/heartbeat/nightly-backup \
-H "Authorization: Bearer $BACKUP_SECRET"
204Ping accepted.
401Wrong secret or unknown id, answered alike.
405Any method but GET and POST.
413Body over 1 KB.
