Install the agent

pulse-agent · Linux · one static binary

The agent only pushes: it opens no port on the host and runs as an unprivileged user. It reads /proc and statfs and sends rates, never raw counters.

Anyone who has it can push samples for this check. The agent sends it with every push.

Container

one check per container, configured here

The container is reported by this host's agent

As the runtime names it

Up when the container runs and is healthy, starting or has no health check. Down when it is missing from the host's list, not running or unhealthy, or when the host check stops reporting. No credentials of its own: the host push carries it.

Restarts are counted within the held-for time, for example more than 3 restarts within 600 s turns the check degraded.

Runtime socket on the host

Socket access is root-equivalent

The agent needs the Docker or Podman socket to read names, state, health and restart counts. Whoever can use that socket controls the host, and a read-only mount does not narrow it. The agent calls only read-only GET routes and never writes to the runtime.

Container names the agent reports, separated by commas. Empty means every container.

Names the agent never reports. Exclude wins over include.

{{includeNote}}

Add to the agent environment

Include and exclude limit what the agent reports; a container it does not report cannot have a check that is up. Without the socket line the agent sends cgroup values only (cpu, memory), no names, state or health, so this check cannot see a stopped container. The unprivileged pulse-agent user also needs read access to the socket, for example through the docker group: that is the root-equivalent step.
