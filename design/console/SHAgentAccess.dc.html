Agent access

Let your AI agent read monitoring data and draft changes through MCP. Optional and off by default. Runs inside this console server, not in pulse-api; the admin token stays on the server.

MCP endpoint

Add this address as a remote MCP server in your agent. It is not a secret; access needs an OAuth sign-in.

How an agent connects

  1. The agent opens a pulse sign-in page in your browser (OAuth, as the MCP spec describes).
  2. You sign in as yourself and pick the scopes the agent may use.
  3. The agent gets its own scoped token. It never sees your password, the instance admin token or any check secret.

Agents act with the rights of the person who connected them, never more. A Viewer’s agent can only read.

What agents can and cannot do

  • Read first. Status, checks, incidents, latency and SLOs.
  • Drafts need confirmation. Draft checks (for example from an OpenAPI file), incident text and routing suggestions wait for a person.
  • No secrets. Header values, tokens and webhook URLs are never returned.
  • Untrusted text. Error messages and response bodies come from the monitored services and can contain instructions aimed at the agent. That is why changes stay drafts.
