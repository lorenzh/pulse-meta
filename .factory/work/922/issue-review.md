## Findings and nonblocking open points

1. **The reported defect is present.** `src/token-routes.ts:126,128` render `state state-error` for missing credentials and a failed self read; line 155 renders `state state-warning` for an expiring last admin token. `src/styles.ts:140-155` styles shared callouts, while neither legacy class has a rule. Replace the two errors with error callouts and preserve the expiry warning as a warning callout. `alertCallout` selects error for ordinary text, so it must not be used blindly for the expiry warning.
2. **The audit covers status messages too.** `test/rendered-audit.ts:7-14` checks every matched `role="alert"` or `role="status"` opening tag for the shared section/classes and rejects inline styles. Removing a role to evade it, weakening its regex, adding legacy CSS or checking only pages without notices would not fix the issue.
3. **More render sites will fail.** In addition to the three sections, token routes have the local paragraph-based `alert` at lines 93-94 and status paragraphs at 162 and 547. Token pages have alert paragraphs at 160 and 201. Probe routes have the local `alert` at 75-76 and status paragraphs at 121-124 and 396; probe pages have alert paragraphs at 108, 182 and 206. These span missing-token/read refusals, mutation refusals, expired forms, log-write warnings, revoked notices and the probe credential warning. All belong in this feature's “any other” repairs. Keep their existing messages, roles, escaping and rendering conditions. Use warning callouts for warnings and success callouts for successful status messages; ordinary refusals use error callouts. Preserve the existing shared expired-form warning behavior.
4. **Seven test files cover the requested six route families.** They are listed below, including both incident suites. Other `server.*.test.ts` matches in setup and form-token tests concern fake `/admin/tokens/self` API replies, not rendering these console routes. “Status page” means the console `/status-page` settings route, not the separate `pulse-status` repository. Notification and status-settings routes already use shared callouts; they still need the audit.
5. **Audit real GET and POST output.** A single happy-path assertion per file could be vacuous. Include error, warning, success and form re-render bodies that the tests obtain. Audit bodies even where the existing assertion only checks status. `src/server.incidents-write.test.ts:918-929` has a raw fetch that reads and discards a response body: handle it as well. Redirects, HEAD with no body, metrics and JSON are not rendered pages. Reuse `expectCalloutsOnly`, existing API fixtures and console helpers; do not introduce another audit or copy server setup.
6. **Avoid expanding the test helper's reach by accident.** `test/signed-in-console.ts` supplies `getPage`, `postForm` and `replyOf` to many suites. Adding an unconditional audit there also reaches unrelated test routes; `test/fixture-routes.ts:60` still renders a plain alert. Keep this change in the seven named suites by calling the existing assertion on their rendered bodies. Global helper rewiring and unrelated account/fixture repairs are outside this issue. Repeated calls to the shared assertion do not require a new helper.
7. **Existing shared renderers suffice.** `src/states.ts` already supplies explicit-kind `callout` and optional plain-text `alertCallout`; `src/html.ts:52` supplies an escaping `paragraph` for a callout body. There is no demonstrated need to change helpers, CSS, dependencies, contract types, API reads/writes or route logic. No design export sync is requested.
8. **Baseline reliability is measured, not assumed.** The plan must select and actually run any controls it calls passing on the recorded base three times, retaining exit codes and observed test counts. Do not infer reliability from a test's name or source. No known-flaky suite may become a mandatory passing baseline control. An unrelated failure is evidence to report and resolve through the review process, not permission to change extra files or weaken checks.
9. **Audit complete pages, not extracted groups.** `src/server.probes.test.ts:111-116` extracts a location by stopping at the first `</section>`. A shared callout introduces a nested section. Keep the audit on the full response, and ensure existing group/credential assertions still check what they intend; adjust that local test extractor if the new nesting requires it, within the already permitted test file.
