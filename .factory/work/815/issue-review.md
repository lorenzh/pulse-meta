## Current behavior and implementation gaps

1. In contract `src/notify-channels.ts:345`, `viewText(max)` uses string `.min(1).max(max)`. It supplies all six notify report text positions: file-channel `id`, each `refs` entry, rejected `channelId`, rejected `reason`, failed `channelId`, and failed `key`. Their limits are 200, 200, 200, 300, 200 and 300 respectively. The existing report test covers ASCII overflow but no supplementary Unicode boundary. R1 explicitly specifies JavaScript `string.length`; the issue corrects R1's mistaken claim about Zod's counting behavior.
2. Contract `envelopeAddress` takes the substring between the last angle brackets without trimming that substring or requiring the closing bracket to end the address. Notify uses `/<([^<>]*)>\s*$/.exec(value)` and `(match?.[1] ?? value).trim()`. Both contract `from` and every `to` entry share the address schema, including channel records and database views.
3. Contract `smtp.clientName` currently requires only nonempty text without whitespace. Notify's `isEhloName` requires length at most 255 and either dotted ASCII hostname labels (1..63 alphanumeric/hyphen characters, no leading/trailing hyphen) or its existing bracketed address-literal predicate. The latter removes an optional case-sensitive `IPv6:` prefix and checks `/^[0-9A-Fa-f:.]+$/`. Match that actual predicate; replacing it with a stricter IP parser would change the requested rule. Do not import a service module into contract or export helpers for testing.
4. `adminNotifyFailedViewSchema` currently relates `state` to nullable `receivedAt` and checks `failedTotal >= failed.length`. It does not require an empty list and zero total for `never`. R1 already states those empty values when there is no report. Existing tests cover a valid empty `never` view but omit contradictory ones.
5. `NotifyFailedEvent` and `ResendCommandState` are already exported by `src/index.ts` and defined in `src/notify-channels.ts` and `src/resend.ts`; only their entries in `docs/index.md` are missing. Do not create exports or change either enum. In particular, the existing resend-state list has nine entries; the old plan's reference to ten is unrelated to this fix.
