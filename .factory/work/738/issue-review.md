## Current behavior and scope search

The array branch drops private incidents and projects public fields. `server.ts:550-572` passes the result to `okAnswer`, which serializes it and computes an ETag. `/api/manual-incidents` does not need the hidden-checks snapshots, so that separate validation cannot prevent the leak. Both hide-details settings are affected.
2. `server.ts:382-435` accepts arbitrary parsed JSON from `fetchJson`, then checks the content type. Its existing invalid JSON, too-large, validation and wrong-content-type result is HTTP `502` with body `{"error":"invalid API response"}`. `proxyApi` (`:638-670`) sends answers without a tag as `Cache-Control: no-store` and does not apply conditional `304` handling to them. The new shape rejection must reach this result, rather than becoming a tagged `200` containing a placeholder or a generic `500` from an uncaught throw.
3. `cachedRaw`, `rawReader`, `proxyAnswer` and `cachedAnswerFor` cache raw reads and derived answers with dependencies. Currently the malformed singleton can become a reusable tagged successful answer. SSR (`ssr.ts`) and syndication read through the same proxy cache. The fix must apply before successful-answer serialization/tagging on every such use.
4. Searched the status source, public assets and e2e sources for manual-incidents readers, `Array.isArray`, and body/raw passthrough expressions. The other direct manual-incidents reader is `poller.ts:getManualIncidents`: its ternary passes a non-array into `validateManualIncidentsResponse`, not to public output. Other ternaries in the poller concern checks/uptime and lead into validation. These are not additional manual-incidents bypasses. Do not turn this narrow repair into general response validation across unrelated routes.

## Open points and assumptions for the plan

- **Failure shape:** use the exact existing proxy `502`/invalid-response body, no ETag and `no-store`. Reject all JSON non-arrays, including otherwise public singleton objects, `null`, strings, numbers and booleans. Do not wrap a singleton into a list or silently substitute `[]`, because those would report a successful read.
- **Filter/caller boundary:** `filterApiBody` currently returns `unknown` and cannot by itself set the HTTP status. Specify how a failed manual-incidents shape is represented and recognized by the server before `okAnswer`. Its exported function must no longer return that manual singleton unchanged. Keep the failure representation local to status; no contract, dependency or wire-version change is needed. Do not prescribe a representation that changes valid-array projection or other routes.
- **Meaning of cached copy:** after a malformed upstream answer has been read, no request may serve its raw or serialized content, reuse an ETag derived from it, or fall back to a previous successful list instead of the invalid-response result. Existing TTL reuse before a new upstream read and internal caching of safe error outcomes can remain as for unreadable upstream responses. The request does not require bypassing every cache on each request or purging all caches immediately when an upstream body changes. Tests must advance the injected clock past the TTL to establish that the new body was actually observed.
- **Existing page state:** preserving the browser poller's previously validated state on refresh failure and the older-API `404` behavior is outside this repair. Those are distinct from serving a cached malformed body. Do not clear validated state or redesign browser caching. Feed/component badge non-array failures must remain `503 unavailable`, with no successful-content ETag; SSR must not render text from the malformed body.
- **Array compatibility:** “keeps its bytes” means the bytes status already serves after its existing privacy projection, not the upstream JSON's formatting or private fields. Preserve ordering, allowed fields, empty lists, legacy public incidents without visibility/publication fields, public feed identities, ETags and conditional `304` behavior. Malformed elements inside arrays keep their current semantics; this issue concerns the top-level non-list shape.
- **Optional getter:** no `review-runtime.ts` remains in the inspected clone. JSON over HTTP cannot carry accessors. The singleton shape guard can reject an in-process non-array before accessing its title, but hardening getters on items inside valid arrays would change a different branch. Assume that broader work is excluded; address it only if the necessary fix naturally uses the same path, without expanding into contract-wide accessor hardening.
- **Ownership:** one implementation target, `status`. The API remains the primary privacy boundary. No API, contract, notify or deploy implementation is required, and no new dependency or repinning is anticipated. Update status's existing documentation of manual-incidents failure behavior as required by its instructions. No route, auth, provider label or comment changes are needed in this state.
