## Open points resolved by assumptions

1. **Meaning of export.** Use the public surface of `src/index.ts`, including type-only exports, runtime exports and types mixed into runtime export clauses. Do not inventory every declaration exported by internal modules: several schemas are deliberately absent from the public entry point. Do not add public exports to make the check easier, and do not use only a runtime import, which erases the 12 missing types.

2. **Meaning of named.** Require a complete, case-sensitive identifier, allowing existing reference styles such as `Validation<T>` and function signatures. A substring search finds only 48 absent names: `AdminConfigSummary` incorrectly counts as documented inside `validateAdminConfigSummary`. Requiring each name to be its own backtick span also changes the baseline: nine already named exports occur in signatures, generic forms or longer spans. Preserve these valid forms. The check enforces name coverage; review of descriptions, types, signatures and error text remains necessary. A dumped list of identifiers alone does not satisfy the documentation requirement.

3. **Check placement and integration.** Prefer a single new `test/docs-inventory.test.ts`, containing the inventory assertion and focused fixture cases, using existing tooling and built-ins. It runs through the existing `bun run check` chain without changing `package.json`, dependencies, lockfile or CI. Avoid a new production helper exported just for tests. The planner must choose a source-reading implementation that handles current named clauses, comments, multiline formatting and inline type modifiers without silently skipping exports. Aliases must use the public name if supported; unsupported export syntax must fail clearly rather than produce a falsely green partial inventory. There is no need to introduce a general documentation generator.

4. **Documentation scope.** Add useful entries beside the existing relevant sections of `docs/index.md`. For a schema name, identify its shape/type and relevant restrictions; for a type, explain its shape or union; for a constant, state its value and meaning. Link shared rules instead of copying every validator rule repeatedly. Where validator behavior is described, use the exact existing error text and default path from source/tests; do not invent new errors or imply Zod schema parsing has the validators' never-throw guarantee. The subscription token schema bounds a string to 128 characters; route-level token-pattern checks are separate (`src/subscriptions.ts`, `docs/index.md:501-508`).

5. **README and conventions.** The new inventory gate changes developer tooling behavior. Include `README.md` in the same change and describe the check in Development. Include a small `AGENTS.md` update documenting the export-documentation convention/check, since that file owns commands and conventions. Keep the plan's `Files:`, each task's files and acceptance, and this review aligned: the recommended exact cumulative allowlist is `AGENTS.md`, `README.md`, `docs/index.md`, `test/docs-inventory.test.ts`. No other existing documentation file is named as a required companion by the target's instructions.

6. **Version and generated files.** Leave the package version, wire version, `src/`, committed `dist/`, package metadata, dependency pins, lockfile and tooling/CI configuration unchanged. Nothing here requires a docs-only release bump. Run the normal build as part of `check`; verify that it leaves dist byte-for-byte unchanged. If the base build is not reproducible, record that independently instead of hiding it with generated changes in this patch.

7. **Dependencies and rollout.** This issue incorporates #823 and does not depend on its implementation. It adds no wire shape or runtime behavior, requires no consumer pin updates and needs no other target task. Historical reviews explain the motivation; their feature implementations must not be redone. Re-enumerate the actual implementation base if main advances; 316/49 is evidence for the inspected SHA, not a permanent fixed export count.
