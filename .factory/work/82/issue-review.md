# Issue review: #82 Status page design with white-label themes

Verdict: specifiable. Only `status` changes. No blocking question.

## Current state (pulse-status `main`)
- `public/index.html` holds all CSS and two palettes (`--bg --text --up --degraded --down --unknown --maintenance --secondary --border --banner-*`), light, dark, and a duplicated `prefers-color-scheme` block. `src/palette.test.ts` parses these blocks by string search (`:root {`, `:root[data-theme="dark"] {`, `:root:not([data-theme="light"]) {`) and checks 4.5:1 pairs. The new variable names and structure replace it, so the test must be rewritten, not just extended.
- `src/render.ts` renders one-line rows, `formatTime` = ISO string, `renderLocations` always prints "N/M locations down", `renderIncidents` lists open incidents only.
- `src/poller.ts` fetches `/incidents?status=open` only. Resolved incidents of the last 7 days need `/incidents?status=resolved` (the API supports it; the contract `Incident` has `openedAt`, `resolvedAt`, `reason`). That needs a second request, filtering by `resolvedAt` within 7 days on the client, and poller/validate tests. If the resolved request fails, the page should degrade like uptime does (the list is optional), not show the error banner. This is an assumption.
- `src/server.ts` serves `index.html` (only injects `data-poll-ms`), `client.js`, and TS modules via type stripping. There is no static file serving, no font serving, no settings. `src/main.ts` reads `PORT`, `PULSE_API_URL`, `POLL_MS`.
- No `@fontsource-variable/*` packages are installed. Both must be added as dependencies (lockfile updated; only the latin subset woff2 is served).

## Assumptions
1. Theme file format: a CSS file with a `:root` block (light values) and a `:root[data-theme="dark"]` block (dark values). Dark under system preference is derived from the same dark values without duplicating them (e.g. a `@media` rule with the same variables is generated by the server from the parsed theme, or the file may use a documented structure). The spec must pick one; the plan should prefer a JSON-free CSS file, because the issue says "theme file" and "CSS custom properties". Alternative: JSON `{ "light": {...}, "dark": {...} }`. A JSON file is easier to validate and to merge with defaults; the plan decides and documents.
2. Fallback: the server merges the operator file over the default theme per variable and per mode, and serves the result inline in the page or as `/theme.css`. Unknown variables are ignored; values are validated (colour, font stack, length) so that a theme file cannot inject CSS or script. An unreadable or invalid file: fail at start with a clear message (assumed), not a silent fallback.
3. `PULSE_STATUS_NAME` default The default name is open: assume the default product name stays "pulse" (the wordmark in mono plus accent block cursor) and the `<title>` uses the name. Logo: `PULSE_STATUS_LOGO` (path or URL). A local file is served by the server under a fixed path; a URL is used as is. Alt text is the name. The plan fixes the exact names; `PULSE_STATUS_THEME` and `PULSE_STATUS_NAME` are given by the issue, logo setting name is a proposal.
4. The theme switch (system/light/dark) and the stored `pulse-theme` key are unchanged.
5. Variable set (fixed, documented): `bg surface rule line-strong field-line text lead muted accent accent-text tint tint-line success success-tint warning warning-tint error error-tint info info-tint`, `font-sans font-mono`, `radius-sm radius-md radius-pill`. Names follow the table in the issue; the CSS custom property prefix (e.g. `--bg` vs `--pulse-bg`) is a plan decision and must be documented. Fonts and radii have no light/dark pair; "every colour has light and dark" applies to the colours.
6. Summary sentence: worst state wins. Wording for the states: down "N checks down", degraded "N checks degraded", maintenance and no data do not count as problems (maintenance shown with `info`). Incident count appended with " · N incident(s) open". Plural: "1 check degraded", "2 checks down". With mixed down and degraded, the summary names the worst state and the plan should decide whether it names both (assumed: worst state only plus incidents). Empty checks list: "No checks configured".
7. Relative times: "3 min ago" computed in the browser from the poll clock (injectable `now` for tests); `<time datetime>` with a title/tooltip showing the exact local time on hover and focus, so the element needs `tabindex="0"`. Tooltip must be reachable by keyboard and not rely on `title` alone (touch/keyboard). Future times (maintenance windows) use "in 2 h".
8. Maintenance "state" colour is `info`, no data `muted`; status never by colour alone (state word always present).
9. Resolved-incident duration format: "12 min", "2 h 5 min".
10. The 7 day window and 44px targets: uptime bars are focusable (`tabindex="0"`) today; they must also be 44px high or exempt. Assumption: bars are data marks with a focusable tooltip, a 44px hit area via padding on the bar group; the plan must say how. The "every interactive element at least 44px" constraint applies to the theme switch options and bars.
11. Demo data ("one up, one degraded, one down with open incident, one in maintenance, one TLS check, two locations") is not in the repo. Assumption: the acceptance check uses a fixture served by a fake API in a test (a local server inside the test, per AGENTS.md) and a manual run against pulse-api with a seeded config; no new demo mode in the product. If a demo script is wanted it goes under `tools/` and is optional.

## Open points for the spec (non-blocking)
- Theme file format (CSS vs JSON), see assumption 1.
- Logo handling: local path vs URL, allowed types (SVG served as `<img>` only, never inlined), size limits.
- Content-Security: fonts and theme are same-origin; no CDN. Consider a `font-display: swap` and `Cache-Control` for font files; add a test that no external URL is in served HTML/CSS.
- Contrast of operator themes is not enforced by the server (the issue asks for tests of the default only). README should state it is the operator's duty; optional warning at start is out of scope.
- Server needs a safe static route for the two woff2 files (fixed allow-list, no path traversal), plus the `@fontsource-variable` package version pinned in `package-lock.json`. The `npm run test` coverage gate (80 %) and SonarJS complexity (<= 15) apply to the new server/theme/render code.
- XSS: theme values and the name are inserted into HTML/CSS; must be escaped/validated.
- The existing `render.test.ts` tests assert the old markup; they are replaced.
- Responsive 390px: no horizontal scroll, long names/URLs wrap (`overflow-wrap:anywhere`), uptime bars (90 per check) must shrink or wrap.
- No-motion: transitions removed under `prefers-reduced-motion`.
- Not specified: favicon, print styles. Out of scope.

## Derived acceptance check
1. `npm run check` passes in pulse-status (lint, typecheck, tests with the coverage gate).
2. The palette test reads the default theme (light and dark, and the system-dark duplicate if any), asserts every theme variable exists, text/status pairs (text, lead, muted, accent-text on bg and surface; success/warning/error/info on bg and on their tint; muted on bg) >= 4.5, and control pairs (`field-line`, `accent` focus ring vs bg) >= 3. Values equal the table in the issue.
3. Render tests: summary sentences for all-up, degraded, down plus open incident, empty; "locations down" shown only when at least one location is down; relative `<time datetime>` with exact local title; TLS days left; objective; maintenance note; open and resolved-in-7-days incident lists with duration; resolved older than 7 days hidden.
4. Server tests: with `PULSE_STATUS_THEME` pointing at a file that only changes `accent` and `PULSE_STATUS_NAME`, the served page carries the new accent and name and still carries all other default variables; invalid/missing file behaviour; fonts served with `font/woff2` from the server; no external font URL in HTML/CSS.
5. Manual: run the server against demo data, view at 390 px and desktop in light and dark; summary line, structured rows, readable times, resolved list visible; keyboard tab order reaches switch and bars; focus ring is a 2px accent outline.
6. README documents every variable, the settings (`PULSE_STATUS_THEME`, `PULSE_STATUS_NAME`, logo), and a minimal example theme.
