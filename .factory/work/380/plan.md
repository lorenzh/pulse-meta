# Spec #380: Checks via API with an admin token, and hot reload

## Goal
Operators change checks, components and maintenance windows through an authenticated api, and the api applies a changed checks file without a restart. The checks file (`PULSE_CHECKS_FILE`) stays the only source of truth.

## Scope and non-goals
In: contract schemas/types/docs for the admin config API; api hot reload, admin write and read routes, metrics, logs, docs, compose and `compose-e2e`.
Out: web console, database as source, multi-tenancy, audit log beyond log lines and metrics, new check types, probe changes (#384 is closed and done), any change to `GET /probe/checks` or probe tokens' rights.
`compose.yaml`, `compose.e2e.yaml`, `compose/` and `scripts/compose-e2e.sh` live in the api repository, so no third target is needed.

## Decisions (from the review's open points)
1. **Schemas.** The contract owns the wire shapes of the write requests and of the responses. The api keeps the file parsers (`parseConfig`, `parseChecksWithSecrets`, in `config.ts`). Write bodies are validated in the api by running the same file parsers on the body (so unknown keys, limits, id rules and `{"env": NAME}` headers behave exactly as in the file), then cross-checked against the contract schema in tests.
2. **Redaction.** Responses return a check's header *names* only; never header values, `{"env": NAME}` references, request bodies (`body`) or heartbeat secrets. A heartbeat check shows `hasSecret: true`. Request bodies carry headers, `body` and `secret` (write-only; a secret can be set or rotated, never read).
3. **Revision.** Revision = `"sha256-<hex>"` of the raw file bytes, sent as a quoted `ETag` header and as `revision` in bodies. `If-Match` is **required** on every write: missing gives `428`, stale gives `412`. `If-Match: *` is not supported (`400`). Rationale: the owner wants two operators not to overwrite each other.
4. **Write path.** Under one in-process lock (a promise chain): read the file bytes, compare the revision, apply the change to the parsed JSON document, validate the whole result with the existing parsers (so references hold), write a temp file in the same directory (mode and owner copied from the original, JSON with 2 spaces and trailing newline), `fsync` it, re-read and compare the revision once more just before `rename` (an external writer racing in the last millisecond remains possible; documented), `rename`, `fsync` the directory, then reload in process synchronously. The response reflects the applied state and carries the new `ETag`. `EROFS`, `EACCES`, `EPERM`, `EBUSY`, `EXDEV` (a single-file bind mount cannot be renamed over) at any write step give `503` with `{"error": "...cause..."}` that names the cause (for example `checks file is read-only (EROFS)`); the temp file is removed.
5. **Reload.** `fs.stat` of the checks file every `PULSE_CHECKS_RELOAD_INTERVAL_MS` (default `5000`; `0` turns polling off; allowed 1000 to 3 600 000), and `SIGHUP`. No `fs.watch` (rename over a bind mount loses the inode). Stat changed (mtime or size or inode) → read the bytes, hash them; hash equal to the current revision → no reload. Hashing only happens on a stat change, so an idle poll is one `stat`. An edit that keeps mtime, size and inode is not seen by polling; `SIGHUP` always reloads and always hashes. A reload parses the whole file with `parseConfig`; invalid or unreadable: keep running config, log exactly one `warn` line `config reload rejected: <path>: <message>` (messages never quote values, as today), count `result="invalid"`. A failing file is remembered by its stat so the same bad file is not logged again every poll. Startup with an invalid file still fails fast.
6. **Apply rules on a valid reload** (one synchronous swap, then clear the read cache):
   - checks: `upsertChecks(new)`; removed checks become inactive as today; changed fields apply at the next probe fetch.
   - components, maintenance windows, heartbeat secrets: replaced wholesale.
   - heartbeat: the evaluator reads secrets, period and grace from the holder per tick; state of an unchanged id is kept; a changed secret takes effect for the next ping.
   - manual incidents: the component-id set is read from the holder; existing incidents that name a removed component keep their stored data and stay readable and resolvable; creating one for an unknown component is refused as today.
   - maintenance windows already active at reload end by their own times; a removed window ends at once.
7. **Mutable config holder.** `createConfigHolder(initial)` in the api returns `{ get(): Config, set(Config): void }`. `createService`, `createApiServer` and `createManualIncidentStore` get getters (`maintenance: () => ...`, `heartbeatSecrets: () => ...`, `components: () => ...`, `componentIds: () => ...`) instead of values. Existing tests keep passing through thin wrappers or updated call sites.
8. **Routes** (all need `Authorization: Bearer <admin token>`; status order: `404` feature off, `401` missing or wrong token, `403` a valid probe token, then `413` too large, `400` bad JSON or `If-Match`, `428`, `503` file not writable, `412`, `422` schema, `409`, `404` unknown id, success). The 503 write probe is a cheap `access(dir, W_OK)` plus the real error mapping at write time.
   - `GET /admin/config` → `200` `{ revision, checks, components, maintenance }` without secrets, with `ETag`.
   - `POST /admin/checks` → `201`, body = redacted check, `Location` header. Existing id: `409`.
   - `PUT /admin/checks/:id` → `200`, full replace; body id must equal path id (`400`); unknown id `404`. A heartbeat replace without `secret` keeps the old secret; with `secret` rotates it. Changing the check type is allowed (secret then required for heartbeat).
   - `DELETE /admin/checks/:id` → `204` (with new `ETag`). `409` naming the first component that lists it, or the first maintenance window (by index) that references it.
   - `POST|PUT|DELETE /admin/components[/:id]` and `/admin/maintenance[/:index]`. Maintenance windows have no id in the file; the api addresses them by their position `:index` of `GET /admin/config` plus the `If-Match` revision (the revision guards against shifts). Deleting a component is refused with `409` while an unresolved manual incident references it.
   - Body size limit 1 MB like other JSON routes (`413`).
9. **Metrics** (bounded labels): `pulse_api_config_reload_total{result="ok|invalid"}`, `pulse_api_config_writes_total{kind="check|component|maintenance",action="create|replace|delete",result="ok|invalid|conflict|stale|readonly|error"}`. No revision label. Both counters pre-registered at 0.
10. **Logs.** One `info` line per successful write: `config write` with `token` (the token *name*), `kind`, `action`, `id`. Failed writes log one `warn` line with status and kind but no body. Never header values, bodies, secrets, tokens.
11. **Contract versioning.** Additive: minor bump; the wire-format version constant is unchanged unless the contract's own rule says otherwise (the implementer follows `src/version.ts` and its test).

## Performance impact
`bench/budgets.json` does not exist in `main` of the api repository, so the kinds of metric are named: idle CPU and idle RSS (a `stat` every 5 s, one holder object: expected change: none measurable, below noise), startup CPU and wall-clock startup (one extra `stat` and hash at start: none expected), load CPU, p95 latency and requests per second of public reads (getters instead of values; the read cache is cleared only on a reload: none expected), peak RSS (a write holds the file text and parsed copy for a moment, a few hundred KB for large files: negligible), test and build CPU (new tests add some seconds to `bun test`: small rise), image size (no new dependency: none). The implementer measures idle CPU and RSS with polling on (default) and off over 60 s on a 100-check file, and `src/bench-reads.ts` before and after, and notes the numbers in the PR. If `bench/` has appeared in `main` by then, run `bun bench/run.ts --a <main> --b <branch>` and check the budgets.

Behavior:
- zod schemas and inferred types, reusing `checkSchema`-family, `componentSchema` and the maintenance schema (not copies): `AdminCheckInput` (a check plus optional write-only `secret` for heartbeat checks, strict), `AdminCheckView` (check with `headers` as a list of names, `hasBody`/no `body`, `hasSecret` for heartbeat), `AdminComponentInput`/`AdminComponent`, `AdminMaintenanceInput`/`AdminMaintenanceView`, `AdminConfigResponse` (`revision`, `checks`, `components`, `maintenance`), `AdminWriteResponse` variants, and the `ErrorResponse` use for 4xx/5xx. View schemas are strict and cannot carry header values, `body` or `secret` (tested by parsing a sentinel-bearing object and asserting rejection or stripping as designed).
- Header constants/doc: `If-Match` required, `ETag` format `"sha256-<hex>"`, the status table of decision 8.
- Export validators in the same style as the existing plain-TS `validate*` functions where the api needs them, plus the schemas.
Checks: `bun test`, lint, type tests (`types.fixture.ts`), `npm run build` (dist). Each new test fails on the old code; paste the mutation output in the PR (as #324 asks).
Done when: CI is green, the new exports are in `dist` and the docs describe them, and the package is released so the api can depend on it.

## Repository: api
Depends on contract (new schemas and types).
Files: `src/config-holder.ts` (new), `src/config-write.ts` (new: lock, revision, atomic write, edit operations, redaction), `src/config-reload.ts` (new: poll and SIGHUP), `src/config.ts` (export what the writer needs, for example parsing a single check/component/window, no behavior change for the file), `src/start.ts` (holder, reload timer, SIGHUP listener, shutdown cleanup, `listening` log gets `reloadIntervalMs` and `configWrites: "on|off"`), `src/server.ts` (admin routes, getters), `src/service.ts`, `src/manual-incidents.ts`, `src/heartbeat.ts` (getters), `src/metrics.ts` (two counters), `compose.yaml` (comment and an opt-in example to mount `./compose:/config` writable; the default stays `:ro`), `compose.e2e.yaml` (writable directory mount of a copy of the e2e checks, `PULSE_CHECKS_RELOAD_INTERVAL_MS=2000`), `compose/e2e/`, `scripts/compose-e2e.sh`, `checks.example.json` untouched, `docs/rest-api.md`, `docs/configuration.md`, `docs/operation.md` (`curl` examples with `If-Match`, `kill -HUP`, read-only mount and how to mount writable), `docs/install.md`, `README.md` if it lists env vars.
Behavior: as in the decisions above. Env: `PULSE_CHECKS_RELOAD_INTERVAL_MS`. `SIGHUP` handler is registered in `main.ts`/`start.ts` through a dep (`onSignal`) so tests do not touch the process.
Tests (each fails on old code; run the mutation, paste failing output in the PR):
- reload: valid edit applies checks, components, maintenance, secrets and clears the read cache; invalid edit keeps config, logs exactly one line, counts `invalid`, same bad file not logged twice; hash-equal touch does nothing; `SIGHUP` reloads; removed check is inactive; startup with invalid file fails.
- write: every status in the order of decision 8 (404/401/403/413/400/428/503/412/422/409/404), 201/200/204 happy paths per kind, file valid JSON after each step and after a failure at each stage (fault injection: failing `rename`, failing `fsync`), temp file removed, mode kept, serialised concurrent writes (second one with the old revision gets 412), 409 naming the component / window, heartbeat secret set/rotate/keep and never read back.
- sentinel test: sentinel header value, `{"env": ...}` name, body and heartbeat secret sent through POST/PUT, then absent from every response (all admin and public routes), every log line, `/metrics`, and the `409/422` error texts.
- contract conformance: every response parses with the contract schemas.
- idle-cost test: with polling on, an idle tick calls `stat` once and no `readFile`.
- `compose-e2e`: with the writable mount, `POST` a check with an admin token → `201`; a probe reports it within one reload period (probe refresh is 60 s: use the `T_RELOAD` timeout, or a 404 on the probe's result to speed it); `GET /checks` lists it; `PUT` changes its name and the status page shows it; `DELETE` removes it and the page drops it; also a hand edit of the file and `kill -HUP` path, and the default `:ro` mount answers `503`.
Checks: `bun test`, lint, typecheck, `scripts/compose-e2e.sh`.
Done when: CI green, the acceptance flow works end to end in `compose-e2e`, docs are updated, and the PR holds the mutation outputs and the idle CPU/RSS numbers.
