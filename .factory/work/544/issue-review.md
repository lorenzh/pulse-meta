# Issue review #544

One target: `website` (`lorenzh/pulse-website`). No contract, API or other target changes. Source: `audits/security/website.md` (in this repo), findings SEC-1 to SEC-6. Checked against the clone in `.repos/website` at `dcb6162` (the commit the audit examined, still `main`).

## Current state (checked in `.repos/website`)
- `src/docs/highlight.ts:80-94`: `LANGUAGES` is a plain `Record<string, fn>`; `highlight()` does `LANGUAGES[language]` and calls the result if truthy, else `escapeHtml(code)`. Any inherited member (`toString`, `valueOf`, `constructor`, `__proto__`, ...) is truthy and gets called with the code text.
- `src/docs/markdown.ts:43-53`: `LANGUAGE_LABEL` plain object; `codeLabel()` returns `LANGUAGE_LABEL[lang] || "Code"` and the result is put into `aria-label="${label}"` **without `escapeHtml`** (line ~96). Language comes from the first word of the fence info string (`markdown.ts:89`). `copyableCommands` (`src/lib/commands.ts`) already uses a `Set` and is safe.
- `src/docs/bump.ts:4`: `DOC_REPOS` plain object. `scripts/bump-docs.ts:36-40` does `DOC_REPOS[key]` for each CLI key and throws a plain `Error("unknown repo ...")` only when the value is falsy. The loop is top-level script code; there is no unit-testable function for the key lookup. `withRepo()` (`bump.ts:53-63`) also uses `k in DOC_REPOS` / `k in merged`, which see inherited members (a config key `constructor`, accepted by `KEY = /^[a-z]+$/`, counts as "known" and would be dropped by `withRepo`).
- `src/docs/fetch.ts:22-51`: `loadDocFile` returns `readFile(final)` on any hit; on a miss it fetches, then `mkdir` + `writeFile(final, text)` directly. fs functions are imported directly; only `fetch` and `cacheDir` are injected. Cache path: `<cacheDir>/<owner>__<name>/<sha>/<docs path>`. Nothing else reads or lists `.cache/docs`.
- `src/build/static-server.ts:16-21`: `fileForUrl` calls `decodeURIComponent` unguarded; `handle` calls it before its `try`, and the server runs `void handle(req, res)`, so a `URIError` becomes an unhandled rejection (process exit 1 under Bun).
- `src/docs/config.ts:39-42`: the rejection message uses `String(file)`; deep nested arrays overflow the stack in `Array.prototype.toString`, and `Object.create(null)` gives `TypeError`. `config.test.ts` asserts no message text containing the value (only error class/other messages), so changing the description is safe.
- Existing tests: `highlight.test.ts`, `markdown.test.ts`, `bump.test.ts`, `fetch.test.ts` (uses a `fake` fetch and `mkdtemp`), `static-server.test.ts` (starts a real loopback server in `beforeAll`), `config.test.ts`.

## Open points and assumptions (none blocking)
1. **Lookup form.** Any of `Map`, `Object.create(null)` or `Object.hasOwn` is acceptable per the issue. Assumption: the plan picks `Map` (or an `Object.hasOwn` guard) for `LANGUAGES`, `LANGUAGE_LABEL` and `DOC_REPOS`. `DOC_REPOS` is exported and used for its key order (`Object.keys(DOC_REPOS)` in `withRepo` and in the error message); the plan must keep the sidebar order and the message `unknown repo "<key>", expected one of api, probe, status, notify, contract, kit`.
2. **`withRepo` `in` checks.** Not named in the issue but the same class (`DOC_REPOS` lookup). Assumption: in scope; switch to own-key checks so a config key such as `constructor` is kept as an "extra" key and not silently dropped. No separate acceptance test required beyond keeping the existing `withRepo` test green; a small test is welcome.
3. **Testing SEC-6.** The script is top-level code with `git`/network side effects. Assumption: move the key-to-repo resolution into a pure exported function in `src/docs/bump.ts` (e.g. `repoForKey(key)` / `resolveRepoKeys(args)`) that throws `BumpError` with the existing unknown-repo message; `bump-docs.ts` calls it. The test asserts every `Object.getOwnPropertyNames(Object.prototype)` name is rejected with that error. Switching from plain `Error` to `BumpError` follows the website rule "throw only `Error` subclasses with a `name`"; the message text stays.
4. **Testing SEC-3 without killing a process.** A test that fails on `main` needs a way to stop the write half-way. Assumption: `loadDocFile` gets an optional injectable writer (or fs deps) in `deps`, defaulting to `node:fs/promises`, in line with the website rule "pass `fetch` and file readers in as dependencies". The test injects a writer that writes part of the text and then throws; it asserts the final path does not exist (no cache hit) and that the next `loadDocFile` fetches again and returns the full text. On `main` the partial file sits at the final path and is returned, so the test fails. Temp file: same directory as the final file, unique name (e.g. pid + random suffix), a suffix that is not `.md` (e.g. `.tmp`), removed best-effort when the write or rename fails; `rename` into place afterwards. A temp file left by `kill -9` is never read. Content length/hash verification on a hit is optional in the audit and **not** required here.
5. **SEC-4 behaviour.** `fileForUrl` returns `undefined` for a malformed escape (catch `URIError` only), so `handle` answers 404 with `404.html`. In addition, `handle` must not leave a rejection unhandled: wrap the whole handler (or attach a `.catch` at the `void handle(...)` call) so any unexpected error still answers (404 or 500) and is not swallowed silently (AGENTS: never swallow an error silently; e.g. answer 500 and log). Test: a request with a malformed escape (built with a raw path, since `fetch` may normalise; e.g. `/%E0%A4%A` or `/%` via `node:http` request) gets 404, and a following `GET /` still answers 200 from the same server. Plus a unit test `fileForUrl(root, "/%") === undefined`.
6. **SEC-5 message.** "Without `String(value)`": assumption: a string entry keeps today's message with the value JSON-quoted; any non-string is described by its kind only (`an array`, `an object`, `a number`, `null`, ...), never by converting it. No `JSON.stringify` of the value (it overflows on deep input too). Test inputs: a `files` entry nested 10,000 arrays deep (built as a string and `JSON.parse`d, or built in code) and `Object.create(null)`; both give `DocsConfigError` naming `repos.<key>.files`.
7. **SEC-1/SEC-2 test scope.** "Every `Object.prototype` member name" = `Object.getOwnPropertyNames(Object.prototype)` (includes `__proto__`, `constructor`, `toString`, `valueOf`, `hasOwnProperty`, `isPrototypeOf`, `propertyIsEnumerable`, `toLocaleString`, `__defineGetter__`, `__defineSetter__`, `__lookupGetter__`, `__lookupSetter__`). For each: `renderMarkdown` of a fenced block with that language and a benign markup body (e.g. `<b>x</b>`) does not throw, the code body appears as `&lt;b&gt;x&lt;/b&gt;`, and `aria-label="Code"`. Also `highlight(code, name)` directly returns `escapeHtml(code)`. Defence in depth (assumption, not required): escape the label in `aria-label` too.
8. **No working payload.** Tests use benign markup only (no links to foreign hosts, no script, no meta refresh), and the PR body does not name the one member name that returns text unescaped. Commit messages and the PR describe the class ("prototype-chain lookup"), not a recipe.
9. **Docs.** README: one line that the docs cache is written atomically (temp file + rename) next to the existing cache description. No other docs change.
10. **Out of scope.** Audit notes N1-N11 (link-check attributes, size caps, `REPO` accepting `..`, `isSafeUrl` input types, `dist/` atomicity, browser pin, etc.) are not part of this issue. No dependency, CSP, budget or CI change.
