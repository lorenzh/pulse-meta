## Open points and working assumptions

1. **Meaning of “no change to forms/token values.”** Presentation markup, classes, wrappers, descriptions and responsive arrangement may change because the requested fixes require them. Preserve form methods/actions, field names/types/values, preset IDs/scope arrays, defaults, validation, retained/redacted input, hidden CSRF/form tokens and their order, replay/busy handling, and all POST effects. Preserve both CSS design-token values and credential/recovery-code contents. Do not change auth, CSP, routes, role decisions, database/schema, dependency pins or lockfiles.

2. **Checks column selection and desktop fit.** The spec should select a concrete reduced/stacked layout before breakdown; it need not ask the user to choose columns. Keep check identity, state and all authorized actions readily visible. Secondary type, target, source and last-result information can share a second line or move to the existing detail page, as the issue allows. Keep filters, source/shadowed distinctions and every action's route/permission. Long values may wrap at natural boundaries or use deliberate display truncation with the full value accessible through the existing detail page. A wrapper that hides/clips the right edge, a tiny font, or forced mid-word breaks does not satisfy fit. Only Checks has the explicit no-horizontal-scroll requirement at 1280; Tokens, Probes and Team may retain contained table scrolling when their intact values require it.

3. **Long values versus “no word breaks.”** Scope this to visible table words and meaningful units, not a requirement that every entire cell occupies one line. Short IDs and role/state labels remain intact; dates may be kept whole or split once between date and time, with each part intact and UTC preserved. Longer names, URLs, email addresses, IDs and status sentences can break at whitespace or deliberate punctuation boundaries (for example `/`, `-`, `@`), never inside an unbroken segment. An unbreakable value may use a contained scroll fallback in the tables that allow it. Preserve copied/submitted bytes when adding visual break opportunities. Do not apply nowrap to all prose, secrets, code snippets or explanatory action-cell notes.

4. **Recovery-code layout.** Preserve all ten complete grouped codes and their order. Fit each 39-character code on one line within the panel at desktop and phone sizes; use responsive columns only when a complete code fits each column. One column and a smaller mono size on phones is acceptable. No ellipsis, hidden suffix, code-format change or horizontal page overflow.

5. **Preset descriptions must reflect real permissions.** Give each of Read, Manage checks, Post incidents and Full access a distinct useful description, using the unchanged arrays `[read]`, `[read, checks, admin]`, `[read, incidents, admin]`, `[read, checks, incidents, admin]`. API `src/token-scopes.ts` confirms that admin also permits token administration and audit reads, and grants are limited to held scopes. Retain that material caveat, either in the relevant descriptions or as a shared explanatory note. Do not imply the three admin presets lack token-management capability. Preserve disabled choices and their missing-scope explanation, the no-default behavior and error associations. Each card has its radio to the left of its label/title; description text may wrap below the title within the text portion.

6. **Buttons and field widths.** Reuse existing primary/secondary/small variants and responsive maximum widths. Save/Create and Copy use intrinsic inline width; Copy uses the small variant with a usable hit target. Specify numeric, ID/name and long-text field width classes in the plan, covering the actual numeric text inputs and existing check/token/probe forms. Controls can fill their assigned bounded wrapper; they should not all stretch across the content column. Keep textarea/URL/secret-output room appropriate to their contents and preserve working plain sign-in/setup layouts. This does not require a new form design or changing field validation.

7. **Sidebar height and mobile behavior.** A stretched full-page sidebar column, optionally containing sticky viewport-height content, resolves the long-page background/border requirement. Test a page taller than the viewport at the top and after scrolling; `height >= 800` alone proves nothing. Keep the established desktop/mobile transition unless the plan gives a concrete reason to change it. On phones all permitted nav links remain one row, with clear hints for content off either edge and keyboard/touch access to Probes and Team. A hint need not imply scrolling beyond an end where there is no further content. Compact the account block to one row with a bounded/ellipsized identity as needed, visible role and reachable Account security/Sign out. Keep the full identity available accessibly; name/email length must not create hundreds of pixels of header height. The plan should state a measurable row-height bound and how long identities are presented without losing account actions or focus outlines.

8. **Overview data and empty/error semantics.** Build tiles/panels from the existing `summarizeChecks` result: Down, Degraded, Unknown, Maintenance, Up and Total; keep zero counts meaningful. State links use the existing `/checks?state=<state>`, and Total uses `/checks`. Count effective active checks from `/checks`, not shadowed/inactive definitions. The unfiltered list may additionally show shadowed definitions as it does today; they are not state-counted checks. Preserve overall-state precedence and API origin/error/rejected-token/no-token handling; never show a failed read as zero healthy checks. Preserve the existing zero-check empty state; zero tiles alongside it are optional. No invented trends, uptime, locations, incidents or new API requests are needed.

9. **Empty Team actions are often correct.** Align permitted links consistently and render a quiet placeholder such as an em dash when no action is permitted, if needed to avoid a visually broken row. Remove only unintended decorative separators. Never add actions to satisfy a visual expectation. Keep target/actor permissions and visually hidden action suffixes. The 2FA header supplies the label once; cell text can be On/Off with its existing meaning.

10. **Inherited exact-layout tests.** #780 explicitly permits a smaller sidebar gutter and reduced/stacked Checks columns, superseding any older exact 236 px sidebar or eight-column expectations where those conflict. Update those literal expectations to the chosen layout, including selectors that assume the ID has its own td. Preserve header/action word integrity, visible data, filters and permission coverage. Existing identity/email tests may need to check the new compact presentation and full accessible identity. Retain typography/color/font, axe, keyboard, CSP, JS-off and native-form regression coverage rather than removing whole test groups.
