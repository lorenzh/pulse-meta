# Issue review: #268 Atom feed and SVG uptime badges (status)

Verdict: can be specified. No blocking question. Target: `status` only (contract/api/notify/config unchanged; feed and badges use data the proxy already fetches).

## Verified current behavior (status `main`)
- `src/server.ts` serves `/`, static files, `/healthz`, `/readyz`, `/metrics` and `/api/*`. The proxy cache (`cachedAnswer`, key = path+query, `PULSE_STATUS_CACHE_MS`, upstream timeout) holds filtered answers for the four allow-listed paths in `api-filter.ts` (`/api/checks`, `/api/incidents?status=open|resolved`, `/api/maintenance`, `/api/uptime`). Filtering (allow-list, hide mode, `sanitizeText`) and `limitResolvedWindow` (7 days, `RESOLVED_WINDOW_MS`) happen in `fetchUpstream` before caching.
- Global headers: CSP (`default-src 'none'`, ...), nosniff, X-Frame-Options DENY, no-referrer. `/api/*` answers `no-store`.
- `/api/uptime` has 90 UTC days per **active** check; the overall `uptime` is `null` without results. Inactive checks are left out of `/checks` and `/uptime` (api docs), so "unknown or inactive" are indistinguishable in the cached data: 404 for both is natural.
- Incidents carry only `id, checkId, openedAt, resolvedAt, reason`; no check name or state. Name and current state come from `/api/checks`.

## Open points (none blocks; plan decides, defaults given)
1. **Absolute links.** Atom needs an absolute status page URL for `<link>`, `<id>` and the feed `self` link. The request `Host` header is attacker-controlled and may be wrong behind a proxy. Default: new optional setting (e.g. `PULSE_STATUS_PUBLIC_URL`, validated http(s), documented in `docs/configuration.md`); without it the feed is not served (404) rather than built from `Host`. Alternative: relative links with `xml:base`. The plan must pick one and test it. Same for badges: none needed.
2. **Entry identity.** Entry `<id>` must be stable across polls and updates: use a `tag:` or `urn:` id from the incident id (not the reason, never a target). Entry `updated` = `resolvedAt ?? openedAt`; feed `updated` = newest entry, or the cache fill time/epoch when empty (must be deterministic, no `now()` churn for cache validity).
3. **Entry title/state.** "check name and state": the incident has no state; use "Open"/"Resolved" for the incident (from `resolvedAt`). Use the check name from `/api/checks`; for an incident of a check no longer listed (inactive/removed) decide: skip the entry (default, consistent with badge 404 and no leak) or use a generic title. Plan to fix this.
4. **Data sources.** Feed needs open + resolved incidents + checks (4 cache keys incl. no maintenance); badge needs checks + uptime. Reuse the existing cached answers via the same keys and `cachedAnswer`, so no new upstream path and no new allow-list entry. The raw cache would be filtered JSON, so hide mode and allow-list apply automatically; the feed must not re-add fields. Note a cold cache triggers the same upstream calls the page makes (at most once per `PULSE_STATUS_CACHE_MS`); `cacheMs=0` means every request fetches, as for `/api/*` today. Test with a counting fetch.
5. **Upstream failure.** Define: feed/badge answer 503 (feed) / an "unavailable" grey badge (badge, 503 or 200?) and are not cached by clients longer than short; no upstream body or error text leaks. Default: 502/503 with `no-store`, plain text body. A badge 404 must not depend on whether upstream failed.
6. **Hide mode.** Hide on: feed entry content has name, state and times only, no reason; hide off: reason included (already sanitized by the filter), escaped. Targets never appear in either mode. The check name is public already (page shows it). Badge shows state and 90-day uptime only; with a `?label=` default of the check name. Confirm the label default does not expose anything the page hides (it does not).
7. **Badge content.** "Current state" values: the page states (`up`, `degraded`, `down`, `unknown`/other, maintenance?). Plan lists the exact states from the contract validators, text and color per state, and `no data` for `uptime: null`. Color contrast: text vs fill must be legible (the repo has palette rules in `theming.md`/`palette.test.ts`); badge colors are fixed, not themed. Two-part layout needs text width: no font metrics, so use an approximate per-character width table (document the limit) or `textLength`. Keep one pure module (`badge.ts`) with no I/O.
8. **`?label=`.** Strict handling: max length (suggest 32 characters, counted in code points), reject (400) or drop on invalid/overlong input? Default: ignore the parameter when empty, answer 400 when over the limit or containing control characters/non-allowed chars; XML-escape `& < > " '`. Unknown query parameters are ignored or 404? Decide, and keep the cache key independent of the label. A 400 for the label must not reveal check existence: check existence first (404), then validate label, or validate label first for all ids; plan picks the order so the answer is the same for known and unknown ids.
9. **Check id validation.** `/badge/<id>.svg`: id is a path segment, percent-decoded once, matched by lookup in the cached checks list (never joined to a path, no regex that could ReDoS). Malformed escapes, extra segments, other extensions, `HEAD` all handled; 404 body and headers identical for unknown and inactive ids (also timing: same code path).
10. **Caching headers.** `Cache-Control: public, max-age=<n>` with n tied to `PULSE_STATUS_CACHE_MS`/`POLL_MS` (e.g. `max(cacheMs, pollMs)` rounded up to seconds, min 1) — the plan must say which. 404 and error answers: short or `no-store`. Add `ETag`/conditional `If-None-Match` only if cheap (optional). `Content-Type`: `application/atom+xml; charset=utf-8` and `image/svg+xml`.
11. **CSP and embedding.** Global CSP stays unchanged. For the SVG response add a restrictive per-response CSP like the `/logo` route (`sandbox; default-src 'none'; style-src 'unsafe-inline'`) so a direct visit runs no script. `X-Frame-Options: DENY` is set globally; `<img>` embedding from other origins (GitHub README via camo) is not blocked by it, but test it is not blocked by anything else (no `Cross-Origin-Resource-Policy: same-origin`). Add `<link rel="alternate" type="application/atom+xml">` to `public/index.html` for autodiscovery (allowed by CSP: no change). Optional.
12. **RSS 2.0.** Optional, "if cheap": default is to skip it; document as non-goal in the spec unless the plan finds it trivial.
13. **XML validity.** Strip characters illegal in XML 1.0 (control chars) from names and reasons before escaping; escape `& < > " '`. Test with `]]>`, `&`, `<script>`, a NUL, and an emoji. No CDATA. A test must parse the output with a real XML parser; there is no XML parser dev dependency in `status` today — the plan must choose: a small well-formedness checker in the test (strict tokenizer) or a devDependency (check `package.json`, lockfile, license). Avoid adding a runtime dependency.
14. **Durations.** Do not show durations in v1 (none required); if shown, `Intl.DurationFormat` (Node 24: verify availability in the runtime and types, or skip).
15. **Docs.** `docs/operation.md` (subscribe, badge snippet, what is public, caching), `docs/configuration.md` (new setting, if any), `docs/index.md`, `README.md` if it lists endpoints. Markdown snippet uses the public URL placeholder, and the docs state: feed and badges are public, unauthenticated, expose check name, state, 90-day uptime, incident times; reasons only with details on.
16. **"Tests fail on the old code".** New tests are routes that do not exist before (404 today); the cache/CSP/allow-list regression tests (`server.privacy.test.ts`, `server.cache.test.ts`) must stay green and be extended with: the allow-list unchanged (no new `ALLOWED_API_PATHS` entry; `/feed.atom` and `/badge/..` not reachable through `/api/`), the upstream-call count unchanged.
17. **Metrics.** `recordHttp(status)` already counts all responses; no new metric required.
18. **Real output check.** "Browser or feed-reader check noted in the PR" is a manual step for the build; the implementer notes what was opened (e.g. run the server against a stub API, open the feed in a reader or validator, view the badge in a browser). Not automatable in CI.

## Assumptions
- Feed path `/feed.atom`, badge path `/badge/<id>.svg` (issue says "e.g."); documented as the stable paths.
- Resolved window for entries = the page's `RESOLVED_WINDOW_MS` (7 days); already applied by the proxy.
- Only `status` changes; no contract change (no new wire types). No dependency on in-flight features beyond #164/#256, already on `main` (allow-list and `/readyz` are in the clone).
- One entry per incident, no maintenance entries (issue says incidents only).
- No auth, no per-feed tokens, no pagination; entry count is bounded by incidents in the window.

## Derived acceptance check
Start `pulse-status` against a stub API with: one up check, one down check with an open incident (reason containing `<&>`), one resolved incident inside the window and one outside, one removed check id.
1. `GET /feed.atom` returns 200, `application/atom+xml`, well-formed Atom (parsed in test); entries only for the open incident and the resolved one in the window, with check name, state, updated time and a link to the status page; special characters escaped; no target/URL host; with hide on no reason, with hide off the sanitized reason.
2. `GET /badge/<up id>.svg` returns 200 `image/svg+xml`, a two-part badge with the state and the 90-day uptime; the down check shows its state; `?label=` replaces the left text, escaped, and an over-long or invalid label is rejected as specified; unknown, removed and malformed ids give the same 404 response.
3. Both responses carry `Cache-Control` matching the cache/poll interval, the global CSP is unchanged, `/api/*` allow-list is unchanged, and repeated requests inside the cache window cause no further upstream calls.
4. Each new test fails on the previous `main`; `npm run check` passes in `status`; the PR notes a real browser or feed-reader check.
