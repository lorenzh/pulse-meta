## Current behavior and gaps

1. **Copying is unconditional at the shared boundary.** `contract/src/validate-core.ts::problem` always calls `schema.safeParse(ownView(schema, value))`. `ownView` recursively builds object, array and record views; unions and recursive JSON values can use `dataView`. `verdict` still returns the original input object on success. Removing these input-view allocations does not mean changing Zod's parsing behavior or exposing its parsed copy as the result.
2. **The own-data behavior is broader than just history arrays.** Existing tests in `test/validate.test.ts`, `test/tokens.test.ts`, `test/audit.test.ts` and `test/admin.test.ts` cover inherited required fields, non-enumerable own fields, own and inherited accessors, records, unions, recursive JSON, constructor/prototype handling, symbol metadata and getter non-execution. An optional accessor can count as absent and leave a value valid; an unknown accessor can be ignored by a permissive schema. Preserve these existing semantics rather than interpreting the issue as requiring rejection of every object that contains any accessor.
3. **There is a top-level array gap already.** `src/validate.ts::arrayProblem` checks `lookupGetter.call(value, i)`, then passes `value[i]` to the item validator without an ownership check. An inherited data element can therefore supply a valid response item. Nested `arrayView` instead uses `ownValue`, so the inherited token-array tests do not establish safety of the top-level history response arrays. The plan must cover both levels; a shortcut based only on absence of getters is insufficient.
4. **The existing timing test cannot prove acceptance.** `test/validate.bench.test.ts` contains both exact workload shapes: 1,000 checks, each with 90 day objects; uptime uses `uptime: 99.5` and `results: 288`, latency uses `p50Ms: 120`, `p95Ms: 340` and `count: 288`. Dates start at 2026-01-01. It performs two warmups and seven runs, but combines both validators into one `performance.now()` elapsed-time result and only asserts a loose five-second bound. It does not report separate CPU medians or an A/B comparison.
5. **An old test explains the copy requirement but exceeds this issue's scope.** `test/tokens.test.ts` asserts that a Proxy with conflicting descriptor/get values is judged by the descriptor, without invoking `get`. The comment on `problem` uses exactly that case to justify always copying. A portable fast-path check cannot generally certify arbitrary Proxies. The new spec must explicitly reconcile that test/comment with the issue's Proxy exclusion instead of silently weakening ordinary own-data tests.

## Open points and assumptions for planning

- **Affected targets and rollout.** Assume one implementation target, `contract`, including regenerated committed `dist/`. The notify comment establishes another beneficiary of the same shared fix; it does not request a separate notifier optimization or new polling benchmark. Consumers pinned to an old SHA will receive the improvement only after pin updates. Document that rollout limitation; if the plan includes consumer pin updates, give them explicit dependencies on the merged contract SHA and acceptance checks. Do not add unrelated service changes or redo #561/#616.
- **Meaning of plain JSON.** The fast-path performance requirement applies to dense arrays and plain objects with own data properties, as produced by `JSON.parse`. It must be automatic at the existing validators, without a caller assertion of trust, a new public validation API, or changes to the wire schema. Preserve support for existing accepted non-JSON JavaScript inputs through the appropriate checked/fallback behavior. Do not prescribe one optimization algorithm during issue review.
- **Baseline identity.** “Main” in the issue means the fast implementation used as side A in the original review, before the unconditional-copy regression. The inspected main snapshot already copies and is not that baseline. The plan must identify and record an immutable pre-regression SHA, ideally the review's actual A, and verify its validator implementation. If the exact reviewer SHA cannot be recovered, document a verified equivalent historical fast-path baseline and why it is comparable. A comparison only against the current slow main cannot satisfy acceptance.
- **CPU method.** Interpret “within 10%” as no more than a 10% regression: candidate median CPU must be at most `1.10 * baseline median CPU` for each workload independently. Faster results pass. Compare both revisions on the same machine with the same Bun version (repository requirement: 1.4.0), dependency versions, fixture data, command and coverage setting. Generate/parse fixtures and load modules outside the measured interval. Use `process.cpuUsage` deltas (user plus system, converted to milliseconds), or an equivalent explicitly documented CPU measurement; elapsed time alone is insufficient. Measure validation at the public exported boundary and assert success and original-object identity outside timing.
- **Reproducibility.** Use two warmups and seven measured runs for each workload on each side. Record raw samples, medians, resolved SHAs, commands, runtime/OS/CPU context and `(B/A - 1) * 100` in the implementation PR. Prefer alternating A/B rounds or otherwise control order and machine load. The historical millisecond values are not absolute budgets across machines. Do not turn the 10% comparison into a fragile unit-test wall-time assertion or change unrelated Factory/stack benchmark budgets.
- **Regression scope.** Require own-data checks for both top-level response arrays and nested history `days`, with valid items supplied only through a prototype, holes and accessor indexes. Keep valid dense own-data controls. Include a mixed array with an ordinary own first item and a later inherited item so a shortcut cannot establish safety from only the first element. Also validate again after replacing an element/property on a previously accepted mutable input; a prior pass cannot grant permanent trust.
- **Proxy compatibility.** Assume no requirement to preserve conflicting Proxy descriptor/get judgments. The plan should narrowly identify any Proxy-only test adjustment and update the obsolete unconditional-copy rationale. Preserve the general non-throwing validator contract and the non-Proxy getter protections; do not use the exclusion as permission to delete the ordinary own-data suite.

## Derived acceptance check

1. A reproducible A/B against the verified pre-regression fast baseline uses the two existing 1,000-by-90 uptime and latency fixture shapes, converted to ordinary JSON-parsed data. For each workload, two warmups and seven CPU samples per revision produce a candidate median no greater than 110% of the baseline median on the same machine. The PR contains the separate numbers, ratios, commands, resolved revisions and measurement context. Verify successful public validation and original-object identity on both sides.
2. All existing non-Proxy own-data tests continue to pass, including nested fields, records/unions/recursive JSON and getter non-execution. Schemas, public types, wire version, path-bearing error behavior and original-object success identity remain compatible. Any Proxy-specific test change is identified and justified solely by the explicit exclusion.
3. New regression tests exercise exported validators and reject inherited data elements at both top-level and nested array positions, including a later inherited element after a valid own element. Sparse and accessor cases remain rejected where an element is required, and accessor counters remain zero. Valid dense own-data inputs still succeed. A repeated call after mutating a previously valid input must reapply the ownership checks. Demonstrate that the inherited-element test fails against an unsafe direct-parse shortcut; the top-level case also exposes the currently inspected `arrayProblem` gap.
4. The contract implementation passes its required `bun run check` with coverage thresholds unchanged, and commits generated `dist/` matching `src/`. No new runtime dependency, public API, wire change or unrelated benchmark-budget change is needed.
