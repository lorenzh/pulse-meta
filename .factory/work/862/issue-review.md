## Open points and assumptions for the spec

1. **Define the accepted characters explicitly.** “Compatible with the generated HTTP header” needs a testable rule. Recommended resolution: after existing trimming/defaulting, allow HTTP field-value characters representable by fetch's ByteString: horizontal tab (U+0009), space/visible ASCII (U+0020–U+007E), and obs-text (U+0080–U+00FF); reject other controls, DEL and characters outside that range. Preserve working Latin-1 names and internal whitespace/punctuation rather than imposing ASCII-only or slug syntax. The existing configured-header validator excludes tabs for its own policy; do not automatically apply that stricter policy to locations, where internal tabs currently work. This rule validates field transport compatibility; it does not introduce a new parser for the parenthesized User-Agent comment. The plan must state the final rule and cover its boundaries.
2. **Preserve normalization and identity.** Apply the additional validation to the existing trimmed location. Keep unset, empty and whitespace-only input as `default`, case sensitivity, the 64 JavaScript UTF-16-unit length limit and the accepted output string unchanged. Do not lowercase, replace, encode, escape or silently truncate invalid characters. Keep `userAgent` output and result identity unchanged for accepted names. A character removed by the existing outer trim does not make the normalized location invalid.
3. **Reject the whole process during settings load.** Even a deployment that currently has only TCP checks must reject an incompatible location. Validation must run before health binding, check loading, scheduling or result posting; it must not depend on fetching an HTTP check first. Existing startup ordering already provides this boundary.
4. **Use a fixed, value-free diagnostic.** The new failure must name `PULSE_LOCATION` and explain the accepted form without interpolating raw/trimmed input, a generated header, credentials or a runtime exception. Preserve the one-line/no-stack startup format and exit 2. Check both stdout and stderr. The request does not require rewriting unrelated existing diagnostics or suppressing normal accepted-location identity in successful-operation logs.
5. **The undisclosed audit fixture is not a blocker.** Derive synthetic regression inputs from the demonstrated parser/header mismatch; no private finding access or published exploit recipe is necessary. Keep public test titles and diagnostics free of the input values. Exercise embedded invalid characters so trimming does not remove the regression. NUL cannot be supplied in a process environment, so cover it through the pure parser/settings boundary, not a child spawn that fails before probe code runs.
6. **Documentation and scope.** Update probe `docs/configuration.md` (the environment table and Location section), plus `README.md` as required by probe instructions; update troubleshooting guidance if adding a diagnostic makes that useful. Explain normalization, defaults, length, accepted character ranges and failure behavior. Do not claim arbitrary Unicode support. No change is needed to API token matching, contract schemas/wire version, scheduling, retries, authentication, quorum, dependency pins, Factory configuration or deployment configuration. No new runtime dependency is needed.
